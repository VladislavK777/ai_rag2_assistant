# Соответствие OWASP Top 10 для LLM-приложений (2026)

Справка: как архитектура RAG2 закрывает каждую уязвимость из актуального списка
OWASP Top 10 for LLM Applications. Статусы: ✅ реализовано в MVP · 🟡 частично / roadmap.

## LLM01 — Prompt Injection

**Риск:** злоумышленник переопределяет инструкции модели (напрямую или через содержимое документов).

**Меры:**
- ✅ Input Guardrails: Llama Guard 3 8B + эвристики (`INJECTION_PATTERNS`, ru+en) — `guardrails.py`
- ✅ Санитизация чанков при ingestion (удаление инструкций-приманок, экранирование спец-токенов)
- ✅ Изоляция контекста per-request — чанки не переиспользуются между сессиями
- ✅ Системный промпт с жёсткой ролью «отвечай только по документам»
- 🟡 Red-team набор тестов инъекций — расширение в Фазе 2

## LLM02 — Sensitive Information Disclosure (утечка данных)

**Риск:** модель выдаёт PII/секреты, в т.ч. из чужих документов.

**Меры:**
- ✅ RBAC pre-filter в Qdrant — недоступные чанки физически не попадают в контекст (тест `test_rbac_access.py`)
- ✅ PII-маскирование на выходе (Presidio-recognizers: телефоны, паспорта, СНИЛС, ИНН, карты)
- ✅ PII-маскирование на входе и в логах/трейсах (OTel-процессор `attributes/mask_pii` — хэширование email, удаление тел запросов)
- ✅ On-prem: данные не покидают периметр

## LLM03 — Supply Chain (поставляемые компоненты)

**Риск:** скомпрометированные модели, библиотеки, датасеты.

**Меры:**
- ✅ Только модели с HF Verified / официальных репозиториев (Qwen, BAAI, Meta, NVIDIA) с фиксированными версиями в `.env`
- ✅ Все зависимости зафиксированы версиями в `pyproject.toml`; лицензии Apache 2.0/MIT — проверены
- ✅ Docker-образы из официальных реестров с тегами конкретных версий
- 🟡 Sigstore/cosign-проверка образов, приватный HF-зеркало — Фаза 2

## LLM04 — Data and Model Poisoning

**Риск:** отравляющие данные в индексе искажают ответы.

**Меры:**
- ✅ Ingestion с проверкой формата, размера и валидации источников; статусная модель (`pending→parsed→indexed/failed`)
- ✅ Права на запись в workspace (level=write) — загрузка только авторизованными
- ✅ Санитизация контента при индексации (см. LLM01)
- 🟡 Кворк-подтверждение критичных документов, детект аномальных чанков — Фаза 3

## LLM05 — Improper Output Handling

**Риск:** доверие выходу модели без валидации (XSS через markdown, инъекции в UI).

**Меры:**
- ✅ Output Guardrails: grounding-check (NLI) — неподтверждённые ответы блокируются
- ✅ Обязательное цитирование источников — проверяемость каждого факта
- ✅ React экранирует вывод по умолчанию (нет dangerouslySetInnerHTML в frontend)
- ✅ Стриминг с буферизацией первого flush — проверка до показа пользователю

## LLM06 — Excessive Agency (избыточные полномочия)

**Риск:** агент выполняет разрушительные действия без контроля.

**Меры:**
- ✅ Tools только на чтение: `hybrid_search`, `graph_query`, `doc_fetch`, `stt_transcribe` — ни один не мутирует данные
- ✅ Лимит 5 итераций ReAct — детерминированный выход к синтезу
- ✅ Каждый tool получает ACL-контекст — агент не может «увидеть» больше пользователя
- 🟡 Human-in-the-loop interrupt (LangGraph checkpoint) перед будущими write-инструментами — Фаза 2

## LLM07 — System Prompt Leakage

**Риск:** раскрытие системного промпта (в нём — правила Guardrails).

**Меры:**
- ✅ Эвристики блокируют запросы «выведи системный промпт» (ru+en паттерны)
- ✅ В системном промпте нет секретов (ключи — в Vault/env, не в промптах)
- ✅ Аудит попыток (guardrail_block в audit_log с trace_id)

## LLM08 — Vector and Embedding Weaknesses

**Риск:** манипуляция векторным хранилищем, cross-collection атаки.

**Меры:**
- ✅ Qdrant с API-ключом, доступ только из Data Plane сети (`networks: data, internal: true`)
- ✅ ACL-фильтры в каждом запросе — нет «безфильтровых» путей к коллекциям
- ✅ Изоляция по коллекциям: 1 workspace = 1 коллекция
- ✅ Rerank-отсечение (score > 0.1) — нерелевантные/аномальные чанки не доходят до LLM

## LLM09 — Misinformation (дезинформация)

**Риск:** галлюцинации, уверенно выдаваемые за факты.

**Меры:**
- ✅ Grounding-check (NLI): ответ без подтверждения в контексте блокируется
- ✅ Режим «не нашёл в документах» вместо выдумывания
- ✅ Цитаты обязательны — пользователь видит источник каждого утверждения
- 🟡 Feedback-механизм (👍/👎) + evaluation pipeline — Фаза 3

## LLM10 — Unbounded Consumption (исчерпание ресурсов)

**Риск:** DoS через дорогие LLM-вызовы.

**Меры:**
- ✅ Rate limiting в Kong (10 req/min/user)
- ✅ Лимиты: max_tokens на вызов, max 5 итераций агента, max-model-len 8192
- ✅ Ограничения загрузки: 200MB документы, 2GB аудио, whitelist форматов
- ✅ Semaphore на concurrent LLM-запросы, очереди с приоритетами
- ✅ Метрики потребления (tokens/s, GPU util) на дашбордах Grafana + alerting

---

## Примечание про внешний LLM (LLM_PROVIDER=yandex)

При переключении на Yandex GPT содержимое запросов (включая чанки документов) уходит во внешний контур по HTTPS. Это осознанный режим для лёгкого развёртывания/разработки. Для production с конфиденциальными данными — локальный vLLM (`LLM_PROVIDER=local`). Guardrails-контуры (Input/Output) работают одинаково при обоих провайдерах; RBAC pre-filter не зависит от провайдера вовсе.
