# ADR-005. Наблюдаемость и логирование

- **Статус:** принято
- **Дата:** 2026-09-01

## Контекст

Требование: логирование и наблюдаемость с первого дня. OpenTelemetry (трейсинг), Prometheus/Grafana (метрики tokens/s, latency).

## Решение

**OpenTelemetry (трейсинг) + Prometheus/Grafana (метрики) + Loki (логи). Всё разворачивается вместе со стеком в docker compose.**

### Три столпа наблюдаемости

| Столп | Инструмент | Что собираем |
|---|---|---|
| **Traces** | OpenTelemetry → Tempo/Jaeger | Полный путь запроса: Gateway → Guardrails → Planner → Retrieval → Rerank → LLM → Output Guardrails. Спаны с атрибутами (кол-во чанков, модель, токены) |
| **Metrics** | Prometheus + Grafana | RPS, latency (p50/p95/p99), TTFT, tokens/s, GPU util/VRAM, длина очереди ingestion, error rate, cache hit |
| **Logs** | Loki + Promtail | Структурированные JSON-логи с trace_id (корреляция с трейсами) |

### Ключевые метрики (SLO-панель Grafana)

| Метрика | Цель MVP | Зачем |
|---|---|---|
| TTFT (time to first token) p95 | < 3 c | Восприятие скорости пользователем |
| Полный ответ p95 | < 15 c | SLA |
| Throughput LLM | > 20 tokens/s | Качество инференса |
| RPS chat | 10 (устойчиво) | Capacity |
| Error rate | < 1% | Надёжность |
| Guardrails block rate | < 5% | Тюнинг ложных срабатываний |
| Retrieval latency p95 | < 500 мс | Qdrant + rerank |
| GPU utilization | 60–90% | Эффективность железа |
| Ingestion queue depth | < 100 | Здоровье пайплайна |

### Инструментирование

- **Автоматическое:** FastAPI, httpx, SQLAlchemy, Celery — через OTel-автоинструментацию.
- **Ручное:** LLM-вызовы (vLLM-клиент), Qdrant-запросы, LangGraph-узлы — кастомные спаны с бизнес-атрибутами:
  - `rag.chunks_retrieved`, `rag.rerank_score_min`, `llm.tokens_prompt/completion`, `guardrails.decision`.

### Аудит-лог (требование ИБ)

Отдельный append-only поток: `who / when / action / resource / decision / trace_id`. Пишется в PostgreSQL (MVP) и дублируется в Loki. События: логин, доступ к документу, отказ Guardrails, экспорт ответа.

### Дашборды (провижинятся автоматически)

| Дашборд | Статус | Состав |
|---|---|---|
| **SLO Overview** | ✅ реализован (MVP) | latency p50/p95, RPS, TTFT, LLM tokens/s, guardrails decisions, ingestion queue depth — `infra/grafana/provisioning/dashboards/rag2-slo.json` |
| **LLM Performance** | 🟡 Фаза 2 | VRAM/утилизация GPU (dcgm-exporter) — целевая GPU-конфигурация |

## Последствия

- Оверхед трейсинга < 3% latency (sampling 10% на проде, 100% в MVP).
- Любой инцидент разбирается по trace_id за минуты, а не часами.
- Дашборды и алерты версионируются в `infra/grafana/provisioning/`.
- В MVP реализован один дашборд (SLO Overview), покрывающий пользовательский опыт (latency, TTFT), трафик (RPS), безопасность (guardrails) и конвейер индексации (queue depth); остальные — Фаза 2, после перехода на GPU-контур и появления фидбека.
