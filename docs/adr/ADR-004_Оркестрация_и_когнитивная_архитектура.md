# ADR-004. Оркестрация и когнитивная архитектура (LangGraph)

- **Статус:** принято
- **Дата:** 2026-09-01

## Контекст

Требование: stateful-оркестрация агентов (LangGraph или LlamaIndex Workflows). Линейные цепочки запрещены. Нужны ReAct / Plan-and-Solve / Multi-Agent.

## Решение

**LangGraph 1.2. Когнитивная архитектура: Plan-and-Solve (планировщик) + ReAct (исполнитель) в одном графе.**

### Trade-off analysis

| Фреймворк | Stateful | Checkpointing | Human-in-the-loop | Контроль графа | Вердикт |
|---|---|---|---|---|---|
| **LangGraph** | Да (TypedState) | Да (Postgres/SQLite saver) | Да (interrupt) | Полный (явные узлы/рёбра/условия) | **Принят** |
| LlamaIndex Workflows | Да (event-driven) | Ограничен | Да | Событийная модель — менее явная | Альтернатива |
| LangChain Chains | Нет (линейные) | Нет | Нет | — | **Запрещён ТЗ** |
| AutoGen | Да | Да | Да | Диалоговая модель — сложнее контролировать | Отклонён |
| CrewAI | Да | Нет | Ограничено | Ролевая модель, менее гибкая | Отклонён |

### Граф агента (state machine)

```
[START] → input_guardrails → planner
    planner → (простой вопрос) → retriever → synthesizer
    planner → (сложный) → react_loop ⇄ tools
    react_loop → synthesizer
synthesizer → output_guardrails → [END / stream]
```

Узлы:
- `input_guardrails` — PromptGuard (injection) + PII-фильтр (см. ADR-006)
- `planner` — LLM-классификация сложности + декомпозиция (Plan-and-Solve)
- `retriever` — hybrid search (BM25 + dense) + rerank
- `react_loop` — ReAct: Thought → Action → Observation, max 5 итераций
- `tools` — `hybrid_search`, `graph_query` (GraphRAG), `stt_transcribe`, `doc_fetch`
- `synthesizer` — генерация ответа с цитатами
- `output_guardrails` — grounding-check + PII-маскирование

### Почему не Multi-Agent Collaboration

Multi-agent (несколько специализированных агентов с общением) даёт прирост на сложных задачах, но:
- ×3–5 latency (каждый агент = LLM-вызовы)
- Сложность отладки и предсказуемости
- Для MVP-сценариев (поиск + транскрипция) избыточен

**Решение:** один граф с planner + ReAct. Multi-agent — Фаза 4 (roadmap), когда появятся сценарии «исследователь + критик + синтезатор».

### Checkpointing

LangGraph `PostgresSaver` — состояние графа сохраняется в PostgreSQL:
- Возобновление прерванных сессий
- Human-in-the-loop (interrupt перед опасными tool-вызовами — Фаза 2)
- Аудит: полная трасса решений агента сохраняется

### Streaming

`astream_events` LangGraph → SSE в frontend. Пользователь видит:
1. Статус («ищу в документах…», «анализирую…»)
2. Токены ответа по мере генерации

## Последствия

- Код графа: `backend/app/agents/graph.py` — единственное место определения логики агента.
- Добавление нового tool = 1 функция + 1 ребро в графе.
- Тестирование: каждый узел — unit-тест, весь граф — интеграционный.
