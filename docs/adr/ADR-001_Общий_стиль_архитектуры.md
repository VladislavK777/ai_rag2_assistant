# ADR-001. Общий стиль архитектуры и технологический каркас

- **Статус:** принято
- **Дата:** 2026-09-01

## Контекст

Нужен стиль архитектуры для MVP, который переживёт масштабирование до 4 000 пользователей и удовлетворяет критерию «Control Plane / Data Plane».

## Решение

**Микросервисная архитектура с разделением на Control Plane и Data Plane.**

### Control Plane (stateless, масштабируется горизонтально)
- `nginx` — TLS-терминация, маршрутизация (/api → backend, /auth → keycloak), rate limiting
- `backend` (FastAPI) — BFF: chat, sessions, admin; resource server (валидация JWT Keycloak)
- `orchestrator` (LangGraph) — агентский граф, внутри backend-процесса в MVP
- `ingestion-worker` (Celery) — парсинг, чанкинг, эмбеддинг документов
- `stt-worker` (Celery) — транскрипция аудио
- `frontend` (React) — SPA
- `keycloak` — SSO-аутентификация (OIDC/PKCE, LDAP federation), единственный источник учётных данных

### Data Plane (stateful, отдельная сетевая зона)
- `qdrant` — вектора + payload (ACL-метки)
- `postgres` — метаданные, RBAC, сессии, логи
- `minio` — исходные документы, аудио
- `vllm` — GPU-инференс LLM
- `vault` — секреты
- `redis` — очередь Celery, кэш

### Trade-off analysis

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| Монолит | Быстрый старт | Не масштабируется по GPU, нет изоляции доменов | Отклонён |
| Микросервисы | Изоляция, независимое масштабирование, чёткие границы | Операционная сложность | **Принят** |
| Serverless/FaaS | Автоскейл | Холодный старт, сложность с GPU, не подходит on-prem | Отклонён |

### Языки

- **Backend: Python 3.12** — экосистема AI/ML (LangGraph, vLLM-клиенты, transformers) недостижима для Go; FastAPI — производительный async-фреймворк.
- **Go** — рассмотрен для API Gateway-слоя и ingestion-воркеров (высокий throughput парсинга), но в MVP это усложнение: один язык = один CI/CD, один стиль тестов. Go может быть добавлен точечно на Фазе 3 для CPU-bound парсеров.

### Frontend

React 19 + Vite 8 + TypeScript. Причины: стриминг SSE из коробки (EventSource), экосистема, найм. Альтернатива (Vue/Svelte) — без существенных преимуществ.

### Секреты

HashiCorp Vault: динамические креды БД, PKI для межсервисного mTLS (Фаза 2), KV для статических секретов MVP. Альтернатива (env-переменные) — только для локальной разработки.

### Аутентификация

Keycloak SSO вместо локальной аутентификации и вместо Kong/JWT-шлюза:
- Пользователи и роли (`ADMIN|EMPLOYEE`) — только в realm `rag2` (в целевом контуре — LDAP federation); пароли пользователей в системе не хранятся вообще.
- Фронт — public OIDC-клиент (authorization code + PKCE); backend — resource server: RS256-JWT по JWKS (кэш, ротация по kid), проверка iss/exp/azp; роли и `employee_no`/`dept_code` берутся из клеймов токена.
- Пользователи в PostgreSQL — для FK и ACL, не для аутентификации.
- Альтернативы: локальные пароли bcrypt — отклонены (нет SSO, парольная политика и аудит на нас); Kong с JWT-плагином — отклонён (лишний сервис для MVP, валидация JWT тривиальна внутри FastAPI).

## Последствия

- 6 сервисов в MVP (nginx, backend, frontend, keycloak, ingestion-worker, stt-worker + data plane) — управляемо docker compose, миграция в K8s — только манифесты.
- Все межсервисные вызовы — через API Gateway или внутреннюю сеть Docker, прямых обращений UI к БД нет.
