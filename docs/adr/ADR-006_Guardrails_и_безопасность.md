# ADR-006. Guardrails и безопасность

- **Статус:** принято
- **Дата:** 2026-09-01

## Контекст

Требование: Input/Output Guardrails (фильтрация PII, защита от prompt injection). Критично: User B не должен получать ответ по секретному документу User A.

## Решение

**Трёхконтурная схема Guardrails.**

### Контур 1. Input Guardrails (до planner)

| Механизм | Реализация | Что ловит |
|---|---|---|
| **Prompt Injection Detector** | Llama Guard 3 8B (классификация) + эвристики (regex на «ignore previous instructions», «system prompt», role-play атаки) | Прямые и косвенные инъекции |
| **PII-фильтр входа** | Microsoft Presidio (NER-модель ruBERT + regex: телефоны, паспорта, СНИЛС, ИНН, карты) | Персональные данные в запросе пользователя |
| **Топик-фильтр** | Список запрещённых тем (политики компании) | Off-topic запросы |
| **Rate limiting** | Kong: 10 req/min/user | DoS, брутфорс |

**Действие при срабатывании:** запрос блокируется, пользователь получает нейтральный отказ, событие пишется в аудит-лог с trace_id.

### Контур 2. Retrieval Guardrails (авторизация данных)

| Механизм | Реализация | Что ловит |
|---|---|---|
| **RBAC pre-filter** | Qdrant payload-фильтр `acl_groups` ДО векторного поиска | Доступ к чужим документам |
| **Изоляция контекста** | Каждый запрос собирает контекст только из разрешённых чанков; чанки не переиспользуются между сессиями | Cross-session утечки |
| **Инъекция через документы** | Санитизация чанков при ingestion (удаление инструкций-приманок «ignore instructions»), экранирование спец-токенов | Косвенный prompt injection из документов |

**Ключевое:** фильтрация на уровне retrieval (pre-filter), а не пост-фильтрация ответа. Модель физически не видит запрещённые чанки → не может их процитировать или пересказать. Это и есть механика критерия «User B не получает ответ по секретному документу».

### Контур 3. Output Guardrails (после генерации, до стриминга пользователю)

| Механизм | Реализация | Что ловит |
|---|---|---|
| **Grounding check** | NLI-модель (cross-encoder) проверяет: каждый факт ответа подтверждён контекстом | Галлюцинации |
| **PII-маскирование** | Presidio на выходе: маскирование ПДн, если документ не разрешает показ | Утечка ПДн в чат |
| **Цитирование** | Ответ обязан содержать ссылки на источники; без источников — режим «не нашёл в документах» | Недоказуемые утверждения |
| **Токсичность** | Llama Guard (тот же инстанс, batch с input) | Оскорбительный контент |

**Действие:** ответ маскируется/блокируется до отправки. При стриминге — буферизация первых предложений (проверка до первого flush).

### Почему именно эти Guardrails

- **Llama Guard 3 8B** — открытая модель-модератор от Meta, дообучена на MLCommons Hazards (13 категорий), работает on-prem, ~50ms на классификацию. Альтернатива NeMo Guardrails — фреймворк, а не модель; сложнее в отладке. Альтернатива «regex-only» — не ловит перефразированные инъекции.
- **Presidio** — индустриальный стандарт PII-detection, поддерживает русский через ruBERT NER, настраиваемые recognizers (паспорт РФ, СНИЛС, ИНН — кастомные regex).
- **NLI grounding** — лёгкая модель (~400MB), детерминированный вердикт entailment/contradiction, дешевле LLM-as-judge.

### Схема потока

```
User → [Input: PromptGuard + PII] → Agent → [Retrieval: RBAC pre-filter]
     → LLM → [Output: Grounding + PII + Цитаты] → User
```

### Секреты и инфраструктурная безопасность

- Vault: все креды, динамические БД-пользователи, PKI (Фаза 2 — mTLS).
- Сегментация: DMZ (frontend, gateway) / Internal (backend, workers) / Data (БД, GPU, Vault) — см. Deployment-диаграмму.
- Шифрование: TLS 1.3 на входе, at-rest — LUKS на дисках + TDE PostgreSQL (Фаза 2).
- Логи не содержат PII: маскирование на этапе записи (Presidio в лог-пайплайне).

## Последствия

- +1 GPU-задача (Llama Guard 8B ~5GB VRAM) — учитано в сайзинге; можно шарить GPU с LLM через time-slicing.
- Латентность +150–300ms на запрос (3 контура) — приемлемо против риска утечки.
- Все решения Guardrails логируются с trace_id → дашборд «Guardrails decisions» в Grafana.
