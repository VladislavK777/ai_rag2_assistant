# ADR-007. Модель данных и хранение

- **Статус:** принято
- **Дата:** 2026-09-01

## Контекст

Нужна модель данных: вектора, чанки, история сессий, логи, права доступа (RBAC). Требование MVP — не усложнять БД.

## Решение

**PostgreSQL 18 (метаданные/RBAC/сессии/аудит) + Qdrant (вектора) + MinIO (файлы).**

### PostgreSQL — основные таблицы

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `users` | Пользователи | id, email, full_name, department_id, is_active, password_hash |
| `departments` | Отделы (для RBAC-иерархии) | id, name, parent_id |
| `roles` | Роли | id, name (admin, user, auditor) |
| `user_roles` | Связь user↔role | user_id, role_id |
| `workspaces` | Рабочие пространства (RAG-базы) | id, name, description, owner_id |
| `permissions` | ACL: кто какой workspace видит | user_id, workspace_id, level (read/write/admin) |
| `documents` | Документы | id, workspace_id, minio_key, title, mime, status, uploaded_by |
| `chunks` | Чанки (метаданные; вектор — в Qdrant) | id, document_id, qdrant_point_id, text, chunk_index, token_count |
| `sessions` | Чат-сессии | id, user_id, title, created_at |
| `messages` | Сообщения | id, session_id, role, content, citations (jsonb), tokens |
| `graph_nodes` | GraphRAG: сущности | id, workspace_id, name, type, description |
| `graph_edges` | GraphRAG: связи | id, src_id, dst_id, relation, weight |
| `audit_log` | Аудит (append-only) | id, ts, user_id, action, resource, decision, trace_id |
| `stt_jobs` | Задачи транскрипции | id, audio_minio_key, status, transcript, summary |

### Qdrant — коллекции

- Коллекция на workspace: `ws_{id}`.
- Point payload: `{ document_id, chunk_id, acl_groups: [dept_ids], acl_users: [user_ids], title, page, created_at }`.
- ACL-фильтр строится из `permissions` + `departments` пользователя и применяется как pre-filter.

### MinIO

- `documents/{workspace}/{doc_id}/{filename}` — исходники
- `audio/{job_id}.wav` — аудио для STT
- Версионирование включено, lifecycle: аудио → удаление через 90 дней.

### RBAC-модель

```
User ──< UserRoles >── Role
User ──< Permissions >── Workspace (read/write/admin)
Department (иерархия) ── наследование прав вниз
```

Проверка прав: `get_user_acl(user_id) → {workspace_ids, dept_ids}` → Qdrant filter. Кэш ACL в Redis (TTL 60 c) — инвалидируется при изменении прав.

### Почему не усложняем

- Нет отдельной БД под сессии/логи — всё в PostgreSQL (MVP).
- Knowledge Graph — таблицы в PostgreSQL, не Neo4j (MVP).
- Аудит — таблица PostgreSQL, не ClickHouse (MVP).
- Миграционный путь зафиксирован: ClickHouse для аудита и Neo4j для графа — Фаза 3, при объёмах >10M событий/мес.
